# Этапы работы и ловушки: REST / GraphQL / gRPC / WebSocket

> Формат: каждый этап = как работает + что ломается на этом этапе.
> ⚠️ = тихий сбой (не видно) · 🔴 = громкий сбой (виден сразу).

---

## 1. REST (HTTP + JSON)

| Этап | Как работает | Ловушки / ошибки этапа |
|---|---|---|
| Проектирование | ресурсы-существительные, глаголы HTTP, статусы | 🔴 глаголы в URL; 🔴 POST=201+Location, DELETE=204; ⚠️ дефолты пагинации менять с анонсом |
| Контракт (DTO+валидация) | аннотации → @Valid ДО контроллера → ControllerAdvice | 🔴 @NotBlank на живом поле = 400 старым клиентам; ⚠️ переименование поля: клиент матчит field→инпут по строке, молча; FieldError без машиночитаемого code |
| Сериализация | DTO + Jackson (NON_NULL, naming) | ⚠️ поле потеряно: нет в DTO / маппер не скопировал / NON_NULL выкинул null / naming сменил имя — всё тихо |
| Шлюзы/посредники | прокси, балансировщики на пути | 🔴⚠️ шлюз подменяет статус на 200-заглушку → RFC 7807 в теле; ссылки строятся без X-Forwarded-Host → битые href |
| Ошибки | RFC 7807 (type/status/detail/instance) | ⚠️ разные форматы ошибок на разных эндпоинтах; кэширование ошибок → no-store |
| Ретраи | идемпотентны GET/PUT/DELETE | 🔴 ретрай POST = дубль ресурса; PATCH — не гарантирован |
| Кэш | GET + Cache-Control/ETag | ⚠️ зашкейлили POST — не кэшируется; устаревший кэш после переименования |
| Эволюция | JSON всё прощает → аддитивное безопасно | ⚠️ чемпион по тихим поломкам: удаление/переименование поля клиент видит как undefined; проверка: javac-jar, OpenAPI-diff, контрактные тесты |
| Безопасность | 401 кто ты / 403 права | ⚠️ токены/PII в URL попадают в логи |

## 2. GraphQL

| Этап | Как работает | Ловушки / ошибки этапа |
|---|---|---|
| Схема (SDL) | типы, input, `!`; контрак = SDL-файл рядом с резолверами | 🔴 required аргумент (!) на живом поле = все старые запросы невалидны; ⚠️ nullable → non-null: null резолвера обнулит data |
| Запрос клиента | query/mutation/subscription + variables | ⚠️ конкатенация значений в текст = нет кэша parse, инъекции; мутации исполняются СТРОГО последовательно, query — параллельно |
| Валидация | по схеме ДО исполнения | 🔴 Cannot query field — громко и рано (тишины как в REST не бывает) |
| Исполнение | резолвер на каждый узел каждого объекта | ⚠️ N+1: 7=1+1+4, у нас 50→51 → DataLoader (один WHERE IN); частичные ответы: data и errors одновременно |
| Ошибки | ВСЕГДА HTTP 200 + errors[] | ⚠️ клиент ветвится по errors, не по статусу; TypedGraphQLError ≠ ControllerAdvice |
| Защита | depth + complexity(веса) | ⚠️ depth слеп к ширине/алиасам/дорогому резолверу → first:100000, алиасы ×200; у нас 20/200, вес 1; интроспекция off в проде |
| Кэш | HTTP-кэш не работает (всё POST на /graphql) | → APQ/persisted queries (шлём хэш), клиентский нормализованный кэш |
| Эволюция | @deprecated(reason) видно в интроспекции | 🔴 удаление/переименование = громко у всех запрашивающих; цикл: новое + deprecated → окно → удалить; schema-diff, кодген |
| Безопасность | авторизация per-field в резолвере | ⚠️ скрыть поле из схемы ≠ закрыть доступ — проверять в резолвере |

## 3. gRPC / Protobuf

| Этап | Как работает | Ловушки / ошибки этапа |
|---|---|---|
| Контракт (.proto) | message+НОМЕРА, service+rpc | 🔴 реюз номера без reserved = каша на старых данных; ⚠️ новые поля = новые номера |
| Кодогенерация | protoc → stub'ы | ⚠️ расхождение версий плагинов у producer/consumer |
| Транспорт | HTTP/2, мультиплексирование | 🔴 прокси/LB не пропускают h2c/trailers; L4-балансировка вместо L7-по-RPC |
| Сериализация | пары (номер, wire type), имён нет | ⚠️ переименование безопасно; 🔴 смена wire-класса (int↔string) = падение парсера; ⚠️ в пределах класса (int32→int64→bool) = ТИХИЙ МУСОР |
| Вызовы | unary / server-stream / client-stream / bidi | 🔴 блокирующий stub внутри реактивного кода; stream без backpressure |
| Ошибки | коды NOT_FOUND/INVALID_ARGUMENT/INTERNAL через trailers | ⚠️ статус в trailers — посредники теряют; не путать с HTTP-кодами |
| Таймауты | deadline propagation по цепочке | ⚠️ без deadline — вечное ожидание нижестоящего |
| Эволюция | номера + reserved + buf breaking в CI | ⚠️ защита структурная, смысла не знает: «count стал supplier_id» протокол не видит |
| Применение | внутрь кластера; REST наружу | ⚠️ браузер напрямую grpc не ест без grpc-web |

## 4. WebSocket (+STOMP)

| Этап | Как работает | Ловушки / ошибки этапа |
|---|---|---|
| Установление | GET + Upgrade: websocket → 101, дальше фреймы поверх TCP | 🔴 прокси/LB не пропускают Upgrade; простаивающие соединения режутся таймаутами → нужен heartbeat |
| Авторизация | в handshake или первом сообщении | ⚠️ токен в query-string handshake попадает в логи |
| Обмен | фреймы 2–14 байт, текст/бинарные; STOMP как прикладной слой | ⚠️ свой протокол поверх = свой разбор/версионирование сообщений |
| Живость | ping/pong, STOMP heartbeat | ⚠️ «мёртвые» сессии копятся: NAT/LB режут тихие соединения |
| Переподключение | клиент с экспоненциальным бэкоффом | ⚠️ события между обрывом и реконнектом ТЕРЯЮТСЯ → replay/дедуп (eventId) |
| Сервер | stateful: сессии в памяти инстанса | 🔴 broadcast только в локальные сессии; масштабирование = sticky + брокер (RabbitMQ) для fanout между инстансами |
| Ошибки | коды закрытия (1000 ок, 1006 обрыв) | нет статусов/ретраев — всё своё; клиент обязан уметь «сервер недоступен» |
| Когда брать | server-push: чат, трекинг, тики | ⚠️ WS «на всякий случай» вместо REST = stateful сложность бесплатно; односторонний push — SSE проще |

## 5. Сводная: та же строка у всех технологий

| Этап | REST | GraphQL | gRPC | WebSocket |
|---|---|---|---|---|
| Контракт | Java-DTO/модуль | SDL-схема | .proto (номера) | своя схема сообщений (STOMP) |
| Профиль поломок | ⚠️ тихий чемпион | 🔴 громкий и ранний | зависит от wire: ⚠️ мусор / 🔴 падение | ⚠️ потеря между дисконнектами |
| Ошибки | статусы + RFC 7807 | всегда 200 + errors[] | коды в trailers | коды закрытия, всё своё |
| Кэш | GET + заголовки | нет (POST) → APQ | нет | нет |
| Ретраи | идемпотентные методы | повтор запроса безопасен | idempotency на своей стороне | replay после реконнекта |
| Совместимость | алиас+code, redirect | @deprecated → окно | reserved + buf breaking | версионирование сообщений |
| Тихий сбой №1 | поле пропало из JSON | depth без complexity | тот же wire = мусор | событие потеряно при обрыве |

**Финальная формула:** REST — CRUD и публичные API; GraphQL — агрегация и форма под клиента; gRPC — внутренние вызовы кластера; WebSocket — server-push. Ошибки каждого профиля закрываются скелетом: термин → механика → компромисс → «в моём проекте…».

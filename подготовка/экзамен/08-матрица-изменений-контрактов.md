# Матрица: все случаи изменения контракта — REST / GraphQL / Protobuf

> Классификация любого изменения: **✅ безопасно** (аддитивное) · **❌ ломает громко**
> (клиент видит ошибку сразу) · **❌ ломает тихо** (клиент не видит ничего — худший случай).
> Правильный путь всегда один: **аддитивность → депрекация (@deprecated/алиас/optional) → окно → удаление.**

---

## 1. REST (JSON-контракт + Java-модуль)

| # | Изменение | Вердикт | Как ломается / как правильно |
|---|---|---|---|
| 1 | Добавить поле в **Response-DTO** | ✅ | Spring-клиенты игнорят неизвестные поля (FAIL_ON_UNKNOWN_PROPERTIES=false). ⚠️ клиенты со строгим десериализатором/валидацией схемы — предупредить |
| 2 | Добавить поле в **Request-DTO** без required | ✅ | Старые клиенты просто не шлют |
| 3 | То же, но сразу с @NotBlank/@NotNull | ❌ громко | Старые клиенты получают 400 по полю, которого у них нет. Правильно: optional → окно → required |
| 4 | Убрать поле из Response | ❌ тихо | Клиент получает undefined без ошибок и логов. Правильно: перестать заполнять → NON_NULL сам скроет → объявить окно → удалить из DTO |
| 5 | **Переименовать поле** | ❌ | Response — тихо (№4); Request — тихо-громко: 400 с новым именем, клиент не понимает, что чинить. Правильно: алиас + code ошибки (В5) |
| 6 | Сменить тип поля (String → Integer) | ❌ | Ошибка десериализации (громко) или семантическая каша (тихо). Тип поля = контракт |
| 7 | **Ужесточить валидацию** (@Size max=50 на живом поле) | ❌ громко | Живые клиенты с длинными значениями получают 400. Ослабить — ✅ |
| 8 | nullable → non-null на поле Request | ❌ громко | Тем, кто слал null, теперь 400. Обратное направление (non-null → nullable) — ✅ |
| 9 | **Новый вариант enum в ответе** | ❌ для типизированных | Jackson бросает InvalidFormatException на неизвестной константе. Учить клиентов: unknown → default. Удалить вариант — ❌ тем же |
| 10 | Новый эндпоинт / новый метод у ресурса | ✅ | Ничего не зацеплено |
| 11 | Удалить / переименовать URL | ❌ громко (404) | Окно: 301-redirect или двойная маршрутизация, потом удалять |
| 12 | Поменять семантику статусов (200 → 201/204) | ❌ тихо | Клиенты и кэши ветвятся по кодам; никто не упадёт, но поведение изменится. Статус = контракт |
| 13 | Поменять формат ошибки (поля ErrorResponse/FieldError) | ❌ тихо | Кто парсил field/message — молча отвалился. Машиночитаемые поля (code) добавлять только аддитивно |
| 14 | Optional-параметр → required | ❌ громко | 400 тем, кто не шлёт. Обратное — ✅ |
| 15 | Изменить дефолты пагинации (size 20 → 50) | ⚠️ поведенческое | Никто не «упал», но потребители получают другие объёмы — менять с анонсом |

**Кто ловит:** javac на потребителях jar (contract-first) · контрактные тесты · OpenAPI-diff. Особенность REST: чемпион по **тихим** поломкам — JSON прощает всё (лишнее игнорит, отсутствующее = null).

## 2. GraphQL (SDL-схема)

| # | Изменение | Вердикт | Как ломается / как правильно |
|---|---|---|---|
| 1 | Добавить поле в тип / новый тип | ✅ | Клиенты не запрашивают неизвестных полей — новое видят только когда попросят |
| 2 | Добавить query / mutation / subscription | ✅ | Аддитивно |
| 3 | Добавить **optional** аргумент (без !) | ✅ | Старые запросы валидны |
| 4 | Добавить **required** аргумент (!) к существующему | ❌ громко | Все старые запросы не проходят валидацию. Только для новых полей |
| 5 | Убрать поле | ❌ громко | У всех, кто его запрашивает: Cannot query field. Правильно: **@deprecated(reason:...)** → окно (видно в интроспекции/кодгене, метрика использования) → удалить |
| 6 | **Переименовать поле** | ❌ громко | То же Cannot query field. Цикл: новое поле + @deprecated на старое → клиенты переезжают → удаление |
| 7 | Nullable → **Non-Null** (добавили !) | ⚠️ | Обещание «null не будет» ужесточилось: если резолвер вернёт null — ошибка уедет в errors и может обнулить весь data. Делать только когда реально всегда есть значение |
| 8 | Non-Null → nullable (сняли !) | ⚠️ | Запросы остаются валидными, но кодген-клиенты получают другой тип (T → T\|null) — сломается компиляция типизированных клиентов = громко для них |
| 9 | Сменить скаляр (String → Int) | ❌ громко | Валидация схемы у всех запросов поля |
| 10 | **Новый вариант enum** | ⚠️ | Падения десериализации у клиентов со строгим маппингом (codegen → unknown value error). Правило для клиентов: unknown → default/ignore. Удалить вариант — ❌ |
| 11 | В input: добавить optional поле | ✅ | Не шлют — не участвует |
| 12 | В input: добавить required поле (!) | ❌ громко | Старые мутации не проходят валидацию. Правильно: optional → окно → ! |
| 13 | Изменить семантику поля без смены типа | ❌ тихо | Схема типы ловит, смысл — нет; имя поля = контракт. Новое поле с новым именем вместо переопределения смысла |

**Кто ловит:** валидация запроса по схеме (громко, у клиента, до сервера) · schema-diff инструменты (graphql-inspector) · кодген: breaking change = ошибка компиляции клиента. Особенность GraphQL: ломается **громко и сразу** — строгая схема, явное перечисление полей.

## 3. Protobuf (.proto)

| # | Изменение | Вердикт | Как ломается / как правильно |
|---|---|---|---|
| 1 | **Добавить поле с новым номером** | ✅✅ | Идеально в обе стороны: старый пропускает неизвестное, новый у старых данных читает дефолт 0/""/false. «Не задано» ≠ «пусто» → optional + hasField |
| 2 | Добавить значение enum | ⚠️ | proto3 сохранит неизвестное число (не упадёт), но switch клиента обязан иметь default/unknown-ветку |
| 3 | Удалить поле | ✅ при **reserved** | reserved 12; reserved "name"; — иначе реюз номера убьёт совместимость (каша на старых сообщениях). В старых байтах поле станет unknown — хранится, не мешает |
| 4 | **Переименовать поле** (номер тот же) | ✅ | Имена по проводу не ездят — только номера. ⚠️ если proto конвертится в JSON наружу (grpc-gateway) — там имена становятся контрактом |
| 5 | Сменить тип **внутри того же wire-класса** (int32→int64→bool→enum, wire 0) | ❌ тихо | Парсинг «успешен», значения — тихий мусор (усечение/переинтерпретация). Хуже падения |
| 6 | Сменить **wire-класс** (int ↔ string) | ❌ громко | Падение парсера: ждал varint, получил length-delimited. Диагноз виден сразу |
| 7 | singular ↔ repeated | ❌ | Интерпретация байтов меняется; старый код увидит один из нескольких блоков |
| 8 | Сменить номер поля | ❌ | = удалить + добавить (№3+№1): старые данные прочитаются как дефолт, новое поле — как неизвестное. Без резкой нужды не делать |
| 9 | message ↔ oneof перекомпоновка | ❌ | Меняется раскладка wire |
| 10 | RPC: добавить rpc | ✅ | Аддитивно; добавить поле в request-message — тоже просто №1 |
| 11 | RPC: удалить/переименовать rpc | ❌ громко | UNIMPLEMENTED у старых клиентов. Окно = держать старый rpc, помечая deprecated |
| 12 | unary ↔ stream | ❌ | Смена сигнатуры вызова; новый rpc рядом вместо изменения |
| 13 | enum-значение переиспользовать под другой смысл | ❌ тихо | Число то же — смысл другой; старые данные «зеленеют» неправильно. Только новые числа |

**Кто ловит:** protoc + **reserved** (компилятор запретит реюз) · **buf breaking** в CI (сравнивает .proto с прошлым релизом). Особенность proto: совместимость живёт на **номерах и wire type**; защита структурная — смысл полей протокол не знает.

## 4. Сводная шпаргалка (как отвечать на любом варианте вопроса)

1. **Безопасное = аддитивное и необязательное:** новое поле/эндпоинт/rpc без ужесточений.
2. **Ломающее =** удаление, переименование, смена типа, ужесточение (required, !, валидация, non-null), смена номера/wire/семантики.
3. **Профиль поломок:** REST — тихий чемпион (JSON всё прощает) · GraphQL — громкий и ранний (валидация по схеме до сервера) · proto — зависит от wire: тот же класс = тихий мусор, другой = громкое падение; номера — единственная правда.
4. **Один цикл на все технологии:** добавить рядом (@deprecated / алиас / optional / reserved для старого) → окно с метрикой использования → удалить.
5. **Смягчение поломок:** REST — машиночитаемые code вместо имён, redirect; GraphQL — @deprecated в интроспекции, unknown→default у клиентов; proto — reserved, buf breaking в CI, default-ветки switch.
6. **Контраст-пара для уточнения:** «как сломается клиент при переименовании?» — REST: тихо (матчит строки) · GraphQL: громко (Cannot query field) · proto: никак (имена не ездят; ломаются номера).

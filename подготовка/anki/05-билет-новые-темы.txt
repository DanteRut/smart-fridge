[GraphQL] Что означает ID! в схеме?	Скаляр-идентификатор с non-null: уникальный ключ (строка или число); клиент НЕ парсит его и не показывает как текст; сериализуется в строку. ! = значение обязательно, null запрещён схемой	anki new ticket
[GraphQL] Что означает String без восклицательного знака?	UTF-8 строка, NULLABLE: значение может отсутствовать — в JSON ключ будет null или его не будет. Nullable в схеме = документированное «может не быть» (courier у заказа)	anki new ticket
[GraphQL] Как читается [String!]!?	Изнутри наружу: список не null И элементы не null. Сравнить: [String]! — список не null, элементы могут быть null; [String!] — список может быть null, элементы нет	anki new ticket
[GraphQL] Когда поле СОЗНАТЕЛЬНО оставляют nullable?	Когда «значения может не быть» — валидное состояние: courier у заказа (ещё не назначен), description у блюда, dish(id) не найден. Nullable — часть контракта, а не небрежность	anki new ticket
[сквозное] HTTP vs WebSocket: базовое отличие модели?	HTTP — запрос-ответ, инициатор всегда клиент. WebSocket — постоянное полнодуплексное соединение: после рукопожатия (GET + Upgrade → 101 Switching Protocols) обе стороны шлют данные когда угодно — настоящий server push	anki new ticket
[сквозное] Почему у WebSocket меньше оверхеда, чем у HTTP?	HTTP несёт заголовки на каждый запрос (сотни байт — КБ); WS после рукопожатия гоняет крошечные фреймы (2–14 байт) поверх одного TCP-соединения	anki new ticket
[сквозное] Когда выбирать HTTP, а когда WebSocket?	HTTP: CRUD, REST-контракты, кэширование, достаточно запрос-ответа. WS: чат, live-трекинг заказа/курьера, биржевые тики, совместные редакторы — события, инициируемые сервером. В зрелых системах соседствуют	anki new ticket
[сквозное] Какие проблемы добавляет WebSocket (4)?	Stateful соединение (масштабирование — брокер/shared state), авторизация в handshake или первом сообщении, переподключение и heartbeat самому, прокси должны пропускать Upgrade, кэшей нет	anki new ticket
[сквозное] Костыли одностороннего push на HTTP?	Long polling (держим запрос открытым: расход коннектов, задержки) и SSE (серверный push в одну сторону, автопереподключение из коробки; проще WS, когда двусторонность не нужна)	anki new ticket

[gRPC] Зачем oneof в proto?	«Свои» данные вариантов без полей-призраков: у фильма режиссёр, у сериала сезоны — одновременно заполнить нельзя (аналог sealed на уровне полей); читающий знает, какой блок присутствует	anki new ticket
